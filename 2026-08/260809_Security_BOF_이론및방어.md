스택 버퍼 오버플로우(BOF) 취약점 실증 실습

학습 일자: 2026년 8월 9일

분류: 보안 / 시스템 해킹

주제: C언어 취약 함수를 이용한 스택 덮어쓰기 및 메모리 변조 확인

1. 실습 목적

이론으로 학습한 스택 메모리 구조를 바탕으로, 입력값 길이를 검사하지 않는 취약한 함수를 사용했을 때 실제로 메모리가 어떻게 오염되고 프로그램이 파괴되는지 직접 터미널 환경에서 검증한다.

2. 취약한 코드 작성

입력을 받는 취약한 부분을 vuln() 함수로 분리하여 작성했다. 만약 오버플로우가 발생해 복귀 주소(RET)가 파괴된다면, main() 함수로 돌아오지 못해 프로그램 마지막의 종료 문구(exit.)가 출력되지 않을 것이다.

3. 프로그램 컴파일 (Windows 환경)

터미널(PowerShell)에서 gcc 컴파일러를 이용해 실행 파일(bof.exe)로 빌드했다.

gcc -o bof.exe bof.c


4. 공격 테스트 및 결과 확인

두 가지 상황을 가정하여 실행 파일을 테스트했다.

정상 입력: 16글자 미만의 정상적인 데이터를 넣었을 때는 vuln() 함수가 안전하게 끝나고 main()으로 돌아와 exit. 문구가 출력되며 정상 종료되었다.

<img width="527" height="110" alt="image" src="https://github.com/user-attachments/assets/0a376417-597b-4d2e-bf0a-50fe426c1473" />

비정상 입력 (오버플로우 공격): 공간 크기를 훌쩍 초과하는 데이터('a' 문자 40개 이상 연속)를 강제로 밀어 넣었다.

[결과]
입력한 값이 출력(good: aaaa...)된 직후, 프로그램이 main()으로 돌아가지 못하고 조용히 튕기며 마지막 exit. 문구가 출력되지 않았다.

5. 실습 결론

넘쳐흐른 데이터가 할당된 공간을 뚫고 나가, 스택 하단에 기록되어 있던 vuln() 함수의 복귀 주소(RET)를 완전히 다른 쓰레기 값으로 덮어써 버렸기 때문에 발생한 현상이다.

함수가 종료되고 main()으로 돌아가려던 CPU가 조작된 주소를 참조하면서 길을 잃어 윈도우 시스템 레벨에서 메모리 참조 에러(Access Violation)를 발생시키고 프로그램을 강제 종료(Crash)시킨 것이다. 만약 공격자가 이 복귀 주소를 자신이 심어둔 악성 코드의 주소로 정교하게 맞춘다면, 프로그램 흐름을 탈취해 시스템 제어권을 넘겨줄 수 있다는 점을 눈으로 확인했다.
