[보안 스터디] Node.js 패킷 스니핑 취약점 실증 및 하드닝 총정리

학습 일자: 2026년 8월 2일

분류: Security / Backend

주제: 인증 메커니즘 이론부터 네트워크 스니핑 실증 및 서버 보안 하드닝까지의 전체 과정 요약

1. 실습 개요 및 목적

HTTP 기반 통신 환경에서 발생할 수 있는 네트워크 패킷 스니핑(Sniffing) 취약점을 실증하고, 이를 방어하기 위한 Node.js 웹 서버 보안 하드닝(Hardening) 절차를 단계별로 수행했다. 이론적 배경을 바탕으로 의도적으로 취약한 서버를 구축하여 공격자의 관점을 이해하고, 미들웨어를 통해 실질적인 방어 아키텍처를 구현하는 것을 목적으로 했다.

2. 단계별 진행 요약

전체 실습은 4개의 단계로 구성되었으며, 각 단계의 상세 내용은 개별 문서로 분리하여 기록했다.

Step 1. 인증 및 웹 보안 기초 이론

관련 문서: 260802_Security_인증및웹보안기초.md

HTTP의 무상태성을 보완하기 위한 쿠키, 세션, 토큰(JWT)의 동작 원리와 장단점을 비교 분석했다.

XSS, CSRF 등 클라이언트 사이드 인증 정보를 노리는 주요 웹 해킹 기법의 원리와 방어 대책(Mitigation)을 정리했다.

Step 2. 취약한 JWT 로그인 서버 구현

관련 문서: 260802_Security_취약한JWT서버구현.md

보안 미들웨어와 HTTPS 암호화가 누락된 Node.js(Express) 서버를 구축했다.

사용자 계정 정보와 서버가 발급한 JWT 토큰을 HTTP Payload(JSON Body)를 통해 평문으로 주고받는 취약한 API 엔드포인트를 설계 및 테스트했다.

Step 3. Wireshark 기반 패킷 스니핑 실증

관련 문서: 260802_Security_Wireshark패킷스니핑.md

로컬 루프백(Loopback) 통신 환경에서 Wireshark를 활용해 중간자 공격(MITM) 시나리오를 검증했다.

패킷 분석 결과, 로그인 요청 시 전송되는 아이디/비밀번호와 서버가 반환하는 JWT 토큰이 암호화 없이 네트워크 상에 완벽히 평문으로 노출됨을 증명했다.

Step 4. 보안 하드닝 및 미들웨어 적용

관련 문서: 260802_Security_서버보안하드닝.md

취약점이 입증된 서버 코드에 3가지 핵심 방어 로직을 적용하여 안전한 서버로 리팩토링했다.

토큰 전달 방식 변경: 응답 본문이 아닌 HttpOnly 및 SameSite 속성이 적용된 쿠키로 전송하여 XSS 공격 방어.

Helmet 미들웨어: 불필요한 서버 정보 헤더 제거 및 HTTP 보안 헤더 강제 적용.

CORS 정책: 허용된 출처(Origin)에서만 API 접근이 가능하도록 설정 제한.

3. 핵심 인사이트 및 향후 적용 방안

본 실습을 통해 애플리케이션 계층의 로직(서버 코드)이 견고하더라도, 네트워크 전송 구간(In-Transit)에 대한 보호가 없으면 데이터가 쉽게 탈취될 수 있음을 확인했다.

로컬 환경의 특성상 HTTP로 실습을 진행했으나, 토큰 기반 인증을 운영 환경(Production)에 배포할 경우 다음 두 가지 조치가 반드시 선행되어야 함을 확인했다.

SSL/TLS 인증서 발급을 통한 전 구간 HTTPS 통신 강제 (스니핑 원천 차단)

인증 쿠키 발급 시 secure: true 옵션 활성화를 통해 암호화된 통신에서만 쿠키가 전송되도록 보장
