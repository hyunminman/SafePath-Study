메모리 오염(Memory Corruption) 취약점 원리 및 방어 기법 분석

학습 일자: 2026년 8월 9일

분류: Security / System Hacking

주제: 스택 버퍼 오버플로우의 작동 메커니즘과 현대 운영체제의 메모리 보호 기법 연구

1. 학습 개요

시스템 해킹의 가장 근간이 되는 메모리 구조를 이해하고, 경계값 검사가 누락되었을 때 발생하는 버퍼 오버플로우(Buffer Overflow) 취약점의 원리를 분석한다. 또한 이를 방어하기 위해 도입된 운영체제 레벨의 방어 기법(DEP/NX, ASLR, Canary)의 메커니즘을 정리한다.

2. 메모리 구조와 Stack의 역할

C/C++ 등으로 작성된 프로그램이 메모리에 적재될 때, 운영체제는 프로세스에 4가지 주요 영역을 할당한다.

Code (Text) 영역: 실행할 프로그램의 기계어 코드가 저장되는 읽기 전용 영역.

Data 영역: 전역 변수와 정적(Static) 변수가 저장되는 영역.

Heap 영역: 런타임에 동적으로 할당되는 메모리 영역 (낮은 주소에서 높은 주소로 확장).

Stack 영역: 함수의 매개변수, 지역 변수가 저장되는 임시 메모리 영역 (높은 주소에서 낮은 주소로 확장).

2.1. Return Address 

Stack 영역에서 가장 중요한 보안적 요소는 RET(Return Address)다. 특정 함수가 호출될 때, CPU는 해당 함수가 종료된 후 원래 실행 흐름으로 돌아가기 위한 주소(RET)를 스택에 저장한다. 공격자의 최종 목표는 바로 이 RET 값을 변조하는 것이다.

3. 스택 버퍼 오버플로우 (Stack BOF) 메커니즘

strcpy, gets, scanf와 같은 함수들은 입력받는 데이터의 길이를 검증하지 않는 치명적인 설계 결함이 있다.

취약점 발현: 할당된 지역 변수(버퍼)의 크기보다 더 큰 데이터를 입력하면, 초과한 데이터가 인접한 메모리 공간을 덮어쓴다(Overflow).

공격 시나리오: 공격자는 의도적으로 버퍼를 넘치게 만들어, 버퍼 바로 아래에 위치한 SFP(Stack Frame Pointer)를 지나 최종적으로 RET를 공격자가 삽입한 악성 코드(쉘코드)의 주소로 덮어쓴다.

결과: 함수가 종료될 때 CPU는 변조된 RET 주소로 점프하게 되며, 이로 인해 원격 코드 실행(RCE) 및 시스템 장악이 발생한다.

4. 메모리 보호 기법 

현대 운영체제는 이러한 메모리 오염 공격을 방어하기 위해 다음과 같은 보호 기법을 적용하고 있다.

4.1. DEP (Data Execution Prevention) / NX bit (No-eXecute)

원리: 메모리 영역에 권한을 분리하여 부여한다. Stack이나 Heap과 같이 '데이터'가 저장되는 영역에는 쓰기(Write) 권한만 부여하고, 실행(Execute) 권한을 제거한다.

효과: 공격자가 버퍼 오버플로우를 통해 Stack에 악성 쉘코드를 주입하고 RET를 그곳으로 돌리더라도, CPU가 해당 영역의 코드를 실행하려 할 때 권한 예외를 발생시켜 프로그램을 강제 종료한다.

4.2. ASLR (Address Space Layout Randomization)

원리: 프로그램이 실행될 때마다 Stack, Heap, 라이브러리(libc) 등의 메모리 주소를 난수화하여 무작위로 배치한다.

효과: 공격자가 DEP를 우회하기 위해 이미 메모리에 적재된 정상적인 함수(예: system)를 호출하려 해도(RTL 공격 등), 해당 함수나 가젯이 메모리상 어디에 위치하는지 알 수 없게 만들어 공격 성공률을 극적으로 낮춘다.

4.3. Stack Canary (스택 카나리)

원리: 할당된 버퍼와 RET 사이에 운영체제가 생성한 임의의 더미 데이터(Canary)를 삽입한다.

효과: 공격자가 RET를 덮어쓰기 위해 버퍼를 넘치게 하면, 물리적 구조상 반드시 중간에 있는 Canary 값도 덮어써지게(변조되게) 된다. 함수가 종료되기 직전 Canary 값의 변조 여부를 검사하여, 변경되었을 경우 오버플로우 공격으로 간주하고 프로세스를 종료(Abort)시킨다.

5. 결론

시스템 공격 기술과 방어 기술은 지속적으로 창과 방패처럼 발전해 왔다. 단일 취약점만으로는 시스템을 장악하기 어려우며, 현대의 익스플로잇(Exploit)은 정보 유출(Leak)을 통해 ASLR을 우회하고, ROP(Return Oriented Programming) 기법을 통해 DEP를 우회하는 등 고도화된 체이닝(Chaining) 기법을 요구한다. 따라서 안전한 소프트웨어 개발을 위해서는 입력값 검증과 더불어 컴파일러 단의 보호 기법 활성화가 필수적이다.
